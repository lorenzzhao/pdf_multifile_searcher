1. How the program is distributed today
---------------------------------------

The program is distributed in two ways:

  - As source code and Python packages (this repository, the wheel and the sdist).
    These do NOT include the third-party components below: pip installs them
    separately from PyPI, and each of them comes with its own license files.

  - As standalone programs for Windows and Linux (installer, portable ZIP, AppImage,
    tar.gz), built with PyInstaller. These DO include the components below and
    therefore follow section 5: every package has a "licenses" folder with the
    license texts and notices, and the release page links the matching source code.

All licenses listed below are compatible with the AGPL-3.0-or-later.

5. Distributing a binary bundle
-------------------------------

Nothing in this section applies to the source distribution described in section 1. A
bundle that contains the dependencies (PyInstaller bundle, AppImage, Flatpak, installer)
must:

  - include LICENSE (AGPL-3.0) and this file;
  - include the texts of the LGPL-3.0 and the GPL-3.0 (the LGPL builds on the GPL),
    and Qt's third-party license notices;
  - keep the Qt libraries as separate shared libraries that users can replace with
    their own modified versions, as the LGPL-3.0 requires;
  - include pypdfium2's LICENSES and BUILD_LICENSES directories and the platformdirs
    license;
  - offer the complete corresponding source code of the program under the AGPL, for
    example with a link to the exact tagged version in the public repository.

The official release packages, built by packaging/pdf-multifile-searcher.spec and the
release workflow, do this as follows:

  - licenses/ contains LICENSE, this file, GPL-3.0.txt, LGPL-3.0.txt,
    QT_THIRD_PARTY_NOTICES.txt (generated by packaging/fetch_qt_notices.py from Qt's
    documentation), and pypdfium2/ and platformdirs/ with their license files;
  - the programs are built in folder mode, so the Qt libraries are ordinary files in
    the _internal folder (Linux: _internal/PySide6/Qt/lib, Windows: _internal/PySide6)
    and can be replaced;
  - every release page links the Git tag of its source code, and GitHub attaches the
    source archives to the release.

Qt modules that the program does not use (for example Qt Quick, Qt QML, Qt PDF and Qt
Network) are left out of the packages, so their notices are not needed.
